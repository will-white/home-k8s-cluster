# Bare-metal rebuild — nuke and repave the whole cluster

Rebuilds the cluster from nothing: blank (or to-be-wiped) nodes, this Git repo,
and the off-cluster backups on the NAS. For a *graceful* full-cluster power
cycle see [full-cluster-shutdown.md](./full-cluster-shutdown.md); for restoring
data after Ceph loss see the
[Ceph DR runbook](../../kubernetes/apps/rook-ceph/rook-ceph/backup/DISASTER-RECOVERY.md)
— this document hands off to its "Full-cluster-loss checklist" once Flux is up.

## What must survive for this to work

| Artifact | Where it lives | Without it |
|---|---|---|
| `age.key` | Workstation repo root; Bitwarden SM (`CLUSTER_AGE_KEY`, via `task bootstrap:secrets-pull`) | Total loss: Talos PKI, Flux deploy key, and the Bitwarden bootstrap token are all SOPS-encrypted to it. **No recovery.** |
| `BWS_ACCESS_TOKEN` | Personal password manager; exported in the workstation shell profile (devcontainer inherits via `localEnv`) | Can't pull `age.key`/deploy key from Bitwarden; ExternalSecrets still work in-cluster because the machine token is SOPS-committed. |
| `github-deploy.key` | Workstation repo root; Bitwarden SM (`CLUSTER_GITHUB_DEPLOY_KEY`) | Regenerate: `ssh-keygen -t ed25519 -f github-deploy.key`, add the pubkey as a GitHub deploy key, re-create `kubernetes/bootstrap/flux/github-deploy-key.sops.yaml` (keys `identity` + `known_hosts`), sops-encrypt. |
| Garage on the NAS (`nas.internal:30188`) | TrueNAS | All PVC + Postgres data gone; cluster still rebuilds, apps start empty. |
| This repo | GitHub (public) | — |

After **any** rotation of `age.key`, the deploy key, or `config.yaml`, run
`task bootstrap:secrets-push` so the Bitwarden copies stay current.

Everything else is derived: `talsecret.sops.yaml` (Talos/etcd/k8s CAs) is
committed encrypted; the NUT upsmon password (`${nut_monpwd}`) is fetched from
Bitwarden SM (`CLUSTER_NUT_MONPWD`) at genconfig time by the bootstrap tasks —
via `scripts/bws-secret.sh`, which decrypts the committed machine token with
`age.key` if `BWS_ACCESS_TOKEN` isn't exported (export `nut_monpwd` manually
to work offline); `kubeconfig` and `talosconfig` are regenerated by the
bootstrap tasks. This means **Bitwarden SM reachability is required for
genconfig** — an accepted cloud dependency (see README).

## 1. Image the nodes

Talos installs to the 250GB SSD (`/dev/sda`); the 500GB NVMe (`nvme0n1`) is
Ceph's. All 8 nodes use Image Factory schematic
`f3350e61fcd45fab42c5b71062eae42982131a4dcbc7ad83bf86d793121607d0`
(gasket-driver, i915, intel-ucode, mei, nut-client — see
`talconfig.yaml`). Boot each node from the matching ISO:
`https://factory.talos.dev/image/f3350e61fcd45fab42c5b71062eae42982131a4dcbc7ad83bf86d793121607d0/<version>/metal-amd64.iso`
(version = `talosVersion` in `talconfig.yaml`). Nodes come up in maintenance
mode on their static DHCP-reserved IPs (`192.168.5.40-42` CP, `.50-.54`
workers).

If the nodes ran Talos before and you still have API access, you can skip the
ISO: `task talos:reset` returns them to maintenance mode — **but see the next
step regardless**.

⚠ **NTP gates boot**: Talos blocks startup until it can reach NTP. If the
router/DNS is also down, nodes sit silently in "waiting for time sync"
(details in full-cluster-shutdown.md).

## 2. Wipe the Ceph NVMe — or Rook will sit at 0 OSDs forever

Rook **refuses** disks carrying old BlueStore signatures and does not log
loudly about it: a rebuild over used NVMe comes up with `0 osds` and no error
in the operator log that names the problem. `task talos:reset` only wipes the
Talos `STATE`/`EPHEMERAL` partitions on `/dev/sda` — **it never touches the
NVMe**. The `sgdisk`/`dd` commands in `kubernetes/apps/rook-ceph/README.md`
can't run on Talos (no shell). Working options:

```bash
# From a running/maintenance node, per node:
talosctl -n <ip> wipe disk nvme0n1

# Or as part of resetting a running cluster:
talosctl -n <ip> reset --graceful=false --reboot \
  --system-labels-to-wipe STATE --system-labels-to-wipe EPHEMERAL \
  --user-disks-to-wipe /dev/nvme0n1
```

## 3. Bootstrap Talos + core apps

```bash
export BWS_ACCESS_TOKEN=<from password manager>
task bootstrap:secrets-pull      # restores age.key, github-deploy.key, config.yaml
task bootstrap:talos
```

This runs: `talhelper genconfig` (decrypts `talsecret.sops.yaml` +
`talenv.sops.yaml` via SOPS/age) → applies per-node configs (`--insecure`
against maintenance mode) → `talosctl bootstrap` (etcd) → fetches kubeconfig →
applies the vendored Gateway API CRDs → helmfile (prometheus-operator-crds,
Cilium, CoreDNS, kubelet-csr-approver, spegel) → waits for nodes Ready.

Gateway API CRDs **must** precede Cilium: cilium-operator checks once at
startup and silently disables its Gateway controller if they're missing.

## 4. Bootstrap Flux

```bash
task bootstrap:flux
```

Applies the GitHub deploy key, creates the `sops-age` secret from `age.key`,
applies `cluster-settings`/`cluster-secrets`, then the root Flux Kustomization.
Flux now reconciles everything under `kubernetes/apps/`.

Note: `kubernetes/flux/config/cluster.yaml` uses the **HTTPS** repo URL, which
works because the repo is public. If the repo ever goes private, switch it to
`ssh://git@github.com/...` — the referenced secret already holds SSH keys.

## 5. IMMEDIATELY suspend the Garage mirror

The daily `rclone-rgw-backup` CronJob (03:00, `rook-ceph` namespace) is a
**destructive sync** RGW → Garage. On a fresh cluster RGW is empty; if it fires
before you restore, **it deletes every backup in Garage**. As soon as the
`rook-ceph` Kustomization reconciles:

```bash
kubectl -n rook-ceph patch cronjob rclone-rgw-backup \
  --type merge -p '{"spec":{"suspend":true}}'
flux suspend kustomization rook-ceph-cluster   # stop Flux reverting the patch
```

## 6. Restore data

Wait for Ceph `HEALTH_OK` and RGW ready, then follow the **Full-cluster-loss
checklist** in the
[Ceph DR runbook](../../kubernetes/apps/rook-ceph/rook-ceph/backup/DISASTER-RECOVERY.md):
rehydrate RGW from Garage (`restore-job.yaml`), then CNPG recovery
(`serverName` bump + `bootstrap.recovery`), then let the Volsync
`ReplicationDestination` bootstraps pull PVCs. The stateful apps' PVCs use
`dataSourceRef` and stay Pending until their restore completes — that is by
design, not a hang.

## 7. Verify, then re-arm

- `flux get ks -A` all Ready; `kubectl get pods -A` clean.
- Ceph: `HEALTH_OK`, OSD count = 8.
- Volsync: canary alert quiet, `kubectl get replicationsource -A` shows recent
  `lastSyncTime` and **non-trivial bytes** (the 2026-05-03 incident was
  restores silently moving 0 bytes).
- CNPG: `kubectl -n database get cluster` healthy, first backup succeeded.
- Gatus (`status.${SECRET_DOMAIN}`) green.

Only then resume the mirror and confirm the next run is **incremental** (an
"everything uploaded" run means it's overwriting, not syncing):

```bash
flux resume kustomization rook-ceph-cluster
kubectl -n rook-ceph patch cronjob rclone-rgw-backup \
  --type merge -p '{"spec":{"suspend":false}}'
```

## Known gaps (tracked, not yet fixed)

- **etcd has no snapshot backups** — quorum loss of 2/3 control planes means
  this full rebuild, not a restore. Helm release history, ACME account/certs,
  and PVC↔PV bindings re-derive slowly (ACME rate limits apply).
- 11 stateful apps have no Volsync coverage (notably komga, kavita, seerr,
  suwayomi) — their data exists only in Ceph and dies with it.
- Garage on the NAS is the only off-cluster tier; there is no offsite copy.
